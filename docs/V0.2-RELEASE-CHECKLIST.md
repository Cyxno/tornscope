# v0.2 Release Checklist

Operational gate for promoting `develop` → `main` and releasing v0.2
(Public Beta 2). Run `scripts/release-preflight.sh` first — it automates the
mechanical checks. Every item here is either PASS / FAIL / UNVERIFIED with
evidence; no optimistic boxes.

## PREPARE

- [ ] Exact release SHA on `develop`: ____________ (== origin/develop, clean tree)
- [ ] Hosted CI green on that SHA (GitHub Actions `verify` + `docker` jobs) — **UNVERIFIED-able only with evidence**
- [ ] Version set everywhere (root package.json canonical; workspace packages match — preflight asserts)
- [ ] Changelog drafted (docs/CHANGELOG-v0.2.md) and honest
- [ ] Migration inventory complete: every migration since `20260909120000_sync_state_last_heartbeat_at` classified in docs/DATABASE-MIGRATIONS.md
- [ ] Backup taken and restore-tested (see §ROLLBACK; pg_dump + restore drill)
- [ ] Production-copy upgrade rehearsal passed (`scripts/rehearse-prod-upgrade.sh --from-prod`) on a backup of the CURRENT production DB
- [ ] Limited-key profile verified (no broken pages, honest unavailable states)
- [ ] Full-key profile verified (all major routes)
- [ ] `scripts/release-preflight.sh` → PREFLIGHT PASS

## DEPLOY (production, when explicitly approved)

- [ ] Announce/freeze: no pushes to develop during the window
- [ ] Fresh backup: `docker exec tornscope-postgres-1 pg_dump -U tornscope -d tornscope -Fc > /mnt/user/backups/tornscope/tornscope-pre-$(date +%Y%m%d-%H%M%S).dump`
- [ ] Production checkout on `main`, clean, == origin/main (`deploy-prod.sh` refuses otherwise)
- [ ] Merge develop → main (fast-forward or merge commit; no squash that loses SHAs)
- [ ] `scripts/deploy-prod.sh` (runs migrate → build → start → ready check)
- [ ] `/api/ready` returns ready; web serves; worker heartbeat present

### Smoke tests (production, post-deploy)

- [ ] `/api/health` reports the expected version + SHA + environment ("Public Beta")
- [ ] Overview, Today, Economy, Progression, Timeline render with real data
- [ ] Sync Status shows resources advancing (nextRunAt in the future)
- [ ] Settings: API-key status, capability matrix, notification devices
- [ ] Header/rail shows the **Beta** chip (never "Development")

## VERIFY (first 24h)

- [ ] Sync backlog drains; no permanently-running resources
- [ ] Notification engine: no unexpected failure logs; test push works
- [ ] No 5xx spikes in API logs; rate-limit engagement logs look like abuse, not outage
- [ ] Progression bars data accumulating (5-min cadence)
- [ ] Mobile (390px): core routes usable, bottom nav works

## ROLLBACK / RECOVERY

App rollback (no DB downgrade needed — migrations are additive):

```bash
cd /workspace/tornscope
git checkout main && git fetch origin
git reset --hard origin/main@{<previous-release-sha>}   # or revert the merge commit
git push origin main                                     # only if the bad commit was pushed
scripts/deploy-prod.sh
```

DB restore (only for data corruption / failed migration — additive
migrations make this unlikely):

```bash
docker compose -f /path/to/docker-compose.unraid.yml stop api worker web
docker exec tornscope-postgres-1 psql -U tornscope -d postgres -c \
  "SELECT pg_terminate_backend(pid) FROM pg_stat_activity WHERE datname='tornscope' AND pid <> pg_backend_pid();"
docker exec tornscope-postgres-1 dropdb -U tornscope tornscope
docker exec tornscope-postgres-1 createdb -U tornscope tornscope
cat /mnt/user/backups/tornscope/<dump>.dump | docker exec -i tornscope-postgres-1 pg_restore -U tornscope -d tornscope --no-owner --clean --if-exists
# verify, then:
docker compose ... start api worker web
curl -s http://127.0.0.1:3100/api/ready   # must be ready before reopening traffic
```

Backup verification (do this NOW, before release):

```bash
docker exec tornscope-postgres-1 pg_dump -U tornscope -d tornscope -Fc > /tmp/rc-verify.dump
docker exec tornscope-test-pg-1 createdb ... # restore into an ISOLATED scratch DB
# compare row counts on User, MoneyEvent, TimelineEvent, PersonalStatSnapshot
```
